# 01 · 架构与模块划分

## 1. 为什么是多模块

项目最初是单模块，后来拆成 5 个 Maven 模块，唯一动机是**让认证内核可以被别的项目整块拿走**：
`qsx-security` 不依赖任何业务代码（用户表长什么样、权限怎么存，它一概不知道），
谁想复用这套「Redis 有状态双 token 会话」只需引 `qsx-common` + `qsx-security`。

拆分的代价是「多了一层依赖纪律」，收益是可复用——所以拆分后的**核心约束只有一条**：
**依赖严格单向、无环**。

```
qsx-admin  →  qsx-module-system  →  qsx-framework  →  qsx-security  →  qsx-common
（可执行）     （业务纵切）          （技术底座）       （认证内核）      （通用契约）
```

## 2. 五个模块

| 模块 | 职责 | 关键约束 |
| :--- | :--- | :--- |
| `qsx-common` | `Result` / `ResultCode` / `BusinessException` + 审计端口契约 `AccessLogRecorder` | **只依赖 lombok**，零业务依赖；不进 Web/ORM/Security 的任何依赖 |
| `qsx-security` | Security 装配、令牌过滤器、Redis 双 token 会话 + Lua、权限缓存、`SecurityUser` / `SecurityUtils` | **不得依赖任何业务模块**；向外取数一律走 `port` 包 |
| `qsx-framework` | MyBatis-Plus 与异步线程池配置、`PageResult`、全局异常处理、操作日志切面 | **不得依赖任何业务模块**；审计落库走 `AccessLogRecorder` 端口 |
| `qsx-module-system` | 认证 / 验证码 / 用户 / 角色 / 权限 / 菜单 / 日志 / Excel 全部业务 + 端口实现 | 包名沿用原单模块；`mapper/adapter` 下是端口实现（必须 `@Component`） |
| `qsx-admin` | 启动类、`application.yml`、集成测试 | 唯一可执行模块；`spring-boot-maven-plugin` 只在这里声明 |

**`qsx-common` 是契约模块，不是垃圾桶**：它只放「谁都要用、且谁都不会反向依赖」的东西。
新增一个工具类之前先问：它能放到 `qsx-framework` 吗？能，就放那里。

## 3. 依赖倒置：三个端口

`qsx-security` 需要一个用户行来认证、需要权限码来授权、需要一个落库入口来写审计日志，
但它**不允许**知道业务表结构。于是三个端口把方向倒过来：

| 端口（`qsx-security` / `qsx-common` 定义） | 实现（业务模块提供） | 用途 |
| :--- | :--- | :--- |
| `AuthUserRepository` | `UserMapper` 的 `mapper/adapter/AuthUserRepositoryImpl` | 按邮箱/ID 取用户行（含逻辑删除过滤语义） |
| `UserAuthorityRepository` | `mapper/adapter/UserAuthorityRepositoryImpl` | 取角色码 / 权限码（**授权语义**，含 `r.status = 0` 过滤） |
| `AccessLogRecorder`（在 `qsx-common`） | `OperationLogServiceImpl` 同时实现 `OperationLogService` 与它 | 审计记录异步落库 |

> **单独复用认证内核时**：必须自己提供上述三个 Bean，否则启动即 `NoSuchBeanDefinitionException`。

## 4. 包路径是契约（移动会静默失效）

这三个包名是**隐式契约**，被扫描规则硬编码。移动它们**不会有任何编译或启动报错**，
只会让对应能力整体落空——这是本仓库最阴险的一类改动：

| 包 | 谁依赖它 | 移动后的症状 |
| :--- | :--- | :--- |
| `com.qsx.web.controller` | `OperationLogAspect` 的 `execution(* com.qsx.web.controller..*.*(..))` | 审计日志再也不落库（接口一切正常） |
| `com.qsx.mapper` | MyBatis-Plus 的 `@Mapper` 扫描 | Mapper 不注册 → 注入失败（这个会报错） |
| `com.qsx.domain.entity` | `mybatis-plus.type-aliases-package` | SQL 里用别名的地方解析失败 |

## 5. 新增业务模块

```bash
# 1. 建模块，pom 只依赖 qsx-framework
qsx-module-<域>/pom.xml

# 2. 控制器放既定包路径即自动纳入审计
com.qsx.web.controller.<域>.XxxController

# 3. 权限码三处同步：init.sql 预置（INSERT IGNORE + 自动绑 ADMIN）、
#    PermissionConstants、控制器 @PreAuthorize

# 4. 在 qsx-admin 的 pom 加一行依赖（唯一需要改内核以外的地方）
```

**不需要改动任何内核代码**——这正是多模块拆分要达到的效果。

## 6. 配置项总览（`qsx-admin/src/main/resources/application.yml`）

| 配置段 | 关键项 | 说明 |
| :--- | :--- | :--- |
| `spring.datasource` | `localhost:3306/QSXManager`，root/123456 | `characterEncoding=utf8` |
| `spring.data.redis` | `localhost:6379`；`timeout: 2s` / `connect-timeout: 1s` | **超时必须显式设置**：默认 60s 会让 Redis 故障时每个请求挂 60 秒 |
| `spring.mail` | `localhost:1025`，无账号密码 | 指向 Mailpit 假 SMTP；**该段缺失会导致启动失败**（`SmtpEmailService` 强依赖 `JavaMailSender`） |
| `mybatis-plus` | `logic-delete-field: deleted`、`type-aliases-package` | `log-impl: StdOutImpl` 仅在本地用，上线应改 `Slf4jImpl` |
| `import.default-password` | 默认 `qsx123456` | Excel 导入用户的统一初始密码，**上线前必须替换** |
| `qsx.rbac-cache` | `enabled` / `ttl: 30m` | 权限缓存；`enabled=false` 退化为实时查库 |
| `qsx.auth.session` | `at-ttl: 30m` / `rt-ttl: 7d` / `max-lifetime: 30d` | **纯数字会被当作毫秒**（`30` = 30 毫秒），启动期有校验兜底 |
| `qsx.captcha` | `debug` / `ttl` / `max-attempts` / `send-interval` / `daily-limit` / `from-address` | 见 [04-邮箱验证码.md](04-邮箱验证码.md) |

## 7. 构建与运行

```bash
mvn -o -DskipTests compile        # 快速编译（依赖已缓存后离线可跑）
mvn -o -DskipTests package        # 打包，只有 qsx-admin 产出 fat jar
java -jar qsx-admin/target/qsx-admin-1.0.0.jar    # 启动，端口 8080

mvn test                          # 全量测试（复用本地 MySQL / Redis / Mailpit）
mvn test -Dtest=SessionLuaTest -Dsurefire.failIfNoSpecifiedTests=false   # 单个测试类
```

两个容易踩的命令坑：

- **不要用 `mvn -pl qsx-admin -am spring-boot:run`**：`-am` 会把其余 4 个模块也拉进 reactor 并
  对它们执行 `spring-boot:run`，它们没有主类 → 直接 `BUILD FAILURE`。
- **指定测试类必须带 `-Dsurefire.failIfNoSpecifiedTests=false`**：多模块 reactor 会让 `-Dtest`
  同时作用于 5 个模块，其余 4 个模块没有匹配的测试类，surefire 默认视为错误并终止构建。
