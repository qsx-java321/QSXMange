## 项目一句话

**用户后台管理基础 demo**：单体多模块（5 个 Maven 模块）、前后端分离，提供可直接复用的
**认证 / 授权 / 用户 / 会话 / 邮箱验证码** 基座。Java 21 · Spring Boot 3.5.16 · MyBatis-Plus ·
MySQL 8.4 · Redis 7.4 · EasyExcel · Spring Mail（本地 Mailpit）。

```
qsx-admin → qsx-module-system → qsx-framework → qsx-security → qsx-common
（严格单向、无环；只有 qsx-admin 是可执行模块）
```

## 全局约定速查（细节见各篇）

- **统一返回**：所有接口返回 `Result{code,message,data}`；**业务异常 = HTTP 200 + body 业务码**，
  仅 401/403 使用真实 HTTP 状态码。断言要看 body 的 `code`，不要看 HTTP 状态。
- **权限码**：`@PreAuthorize("hasAuthority('xxx')")`；新增权限码要同步**三处**
  （`sql/init.sql` 预置 + 自动绑 ADMIN、`PermissionConstants`、控制器注解）。
- **会话**：Redis 是令牌有效性的唯一真相源；涉及账号状态或凭据的变更**必须**调
  `AuthSessionService.remove(userId)` 回收会话。
- **包路径是契约**（移动会静默失效，不报错）：`com.qsx.web.controller`（审计切点）、
  `com.qsx.mapper`（`@Mapper` 扫描）、`com.qsx.domain.entity`（type-aliases，当前无消费方）。
- **测试**：复用本地开发库与开发 Redis；只清 `*@test.com` 测试用户与 `test-` 前缀角色，
  绝不能全表删除（会删掉预置超管）。每个用例前还会**复位预置超管**（口令 hash + `must_change_password=0`），
  所以本地手工改过的超管口令跑一次测试就被还原。
