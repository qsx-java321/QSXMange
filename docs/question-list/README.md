> ## ⚠️ 警告（务必先读）
>
> 本目录所有文档——问题清单、搁置判断、修复方案——均为**梳理整理时的参考意见**，
> 基于当时的源码与设计文档归纳，**不代表最终结论、不保证绝对正确**。其中可能存在：
> 误判、漏项、方案与既有代码风格/架构不契合、因后续代码演进而失效的内容。
>
> **后来者须知**：
> 1. 使用本目录前，**必须结合对应位置的当前代码与设计文档重新分析**，自行核实问题是否仍存在、
>    方案是否仍适用；
> 2. **不要太相信本目录的内容**，可随时批判、优化、完善——发现错误请直接修正并同步更新本文档；
> 3. 任何修复落地前，先看源码与 `docs/design` 对应篇章，再按源码情况定稿，**禁止照搬**；
> 4. **被推翻的结论要留痕**：本目录已发生过一次「P0 级问题的机制前提不成立」（#3），
>    撤销时保留原编号并改写状态，不要删条目——否则下一个读的人会重新踩进去。
>
> 一句话：**这里只是索引与草稿，代码才是真相。**

## 阅读前提

本项目的定位是**本地开发 / 学习阶段的项目，不以真实投产为目标**，追求的是
「按企业级开发的严谨程度把代码写对」。因此：

- 这里登记的是**这批代码在严谨尺度下客观存在的缺陷**，而不是「上线阻塞项」——即使永不上线，
  其中多数（校验缺失、静默失效、口径不一致、审计丢行）也值得当成工程练习修掉。
- 严重度反映**缺陷本身的性质**（P0 = 会导致系统失控或不可恢复；P1 = 功能失效 / 静默不一致 /
  可被利用的缺口；P2 = 工程规范 / 健壮性 / 容量），**不表示修复排期**。
  已明确不修的项一律进 [02](02-主动放弃与搁置清单.md)，不在清单里留模糊状态。
- 每条都标了**「本地可复现」口径**：✅ 本机实测复现过 · 本地可触发（需刻意为之）·
  仅并发/故障/部署形态（单人本地开发遇不到）。

  及本目录内多处引用），**永不重排、永不复用**；新增项从 **#41** 起顺序追加；
  撤销的项保留编号、只改状态列。
- **每条问题必须给证据**：位置（`文件:行号`）+ 触发条件 + 后果。实测复现的记入
  [04](04-实测记录与核验方法.md)，代码推导的注明「未实测」。

  （否则"漏实现"的代码也能写出绿色的用例）。
- **修复类改动要验证「回退后确实转红」**，但注意 [04](04-实测记录与核验方法.md) §7.3 的教训：
  对"删除/替换"类闸门，红跑**必须先备份数据**。
