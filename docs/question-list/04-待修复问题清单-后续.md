## 附 A：问题 4（默认凭据）方案骨架

**核心思路**：用"强制首次改密"一条链同时化解 `admin123` 与 `qsx123456` 两个公开口令，再叠加纯配置整改。

**A-a 强制首次改密（跨模块，本阶段最大改动）**
- 波及文件（已对照源码核查）：
  - `sys_user` 加列 `must_change_password TINYINT NOT NULL DEFAULT 0`；`init.sql` 预置超管 =1；
  - entity `User`、[AuthUserAccount（port record）](file:///d:/Java_SE/Git/QSXManager/qsx-security/src/main/java/com/qsx/security/port/AuthUserAccount.java)（**契约变更**，需同步业务侧 `AuthUserRepository` 实现与 [SecurityUser](file:///d:/Java_SE/Git/QSXManager/qsx-security/src/main/java/com/qsx/security/model/SecurityUser.java)）；
  - 导入 `importUsers` 落库置 1；后台建号（`user:create`）建议置 1；
  - 登录 `LoginVO` 增 `mustChangePassword` 标志；改密成功（含 forgot/change 双通道）置 0；
  - 强制拦截：`TokenAuthenticationFilter` 校验该标志 → 放行白名单 `change-password` / `logout` / `me`，其余返回新业务码 1036（**注意：1036 已被 #21 占用，实施时另取 1037**）。
- 取舍：不做"启动检测默认 hash 失败即拒"（本地环境会被锁），该 fail-fast 仅作为生产形态可选叠加。

**A-b 纯配置整改（零测试影响，可先行）**
- `mybatis-plus.configuration.log-impl: StdOutImpl → Slf4jImpl`；`logging.level.com.qsx: debug → info`；
- `spring.datasource.password: ${DB_PASSWORD:123456}`、`import.default-password: ${IMPORT_DEFAULT_PASSWORD:qsx123456}`。
