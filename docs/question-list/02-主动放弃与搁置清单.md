# 02 · 主动放弃与搁置清单

> 本地/学习阶段**有意搁置**的项与设计取舍。搁置 ≠ 否认风险，而是「当前阶段收益/代价不成比例」的明确决策；每项均附理由与"什么条件下需要重新评估"。

## 一、问题清单中的搁置项

| # | 项 | 严重度 | 搁置理由 | 何时需重新评估 |
| --: | :--- | :--- | :--- | :--- |
| 5 | `qsx.captcha.debug=true` 直返码 | P0 | 本地联调专需（Mailpit 未启动时的逃生口）；配置默认 `false`，切真实邮件环境即自然关闭 | 上线前必须落地"生产 profile 下 debug=true 启动即拒"（并入 #4 家族一并出方案） |
| 6 | Mailpit 本地假 SMTP | P0 | 本地设施；接口"返回成功但收不到邮件"是异步投递的已知语义，本地可接受 | 公网部署前接真实邮件服务商（SMTP 只改配置） |
| 11 | 删除用户残留 `sys_user_role` 孤儿行 | P2 | 重新注册是新 userId，不继承角色 ⇒ 无身份盗用风险，仅脏数据 | 若上线后做数据治理/统计，顺手补清理 |

## 二、设计取舍（明确不修，避免误当 bug 修）

| 取舍 | 说明 | 边界 |
| :--- | :--- | :--- |
| 会话层 fail-closed | Redis 故障 = 拒绝认证（宁可不放行）；权限缓存层才 fail-open（降级查库）。**两边界不可混淆** | 部署须配 Redis 监控告警（见 04 #12） |
| 会话/验证码脚本仅支持单节点 Redis | 键无 hash tag，上集群会 CROSSSLOT；Redis 禁 `allkeys-lru` 淘汰（会话键被淘汰 = AT 无法吊销） | 生产若上集群需重写脚本（大改，别轻易动） |
| `/api/logs` 不进审计（问题 16） | 防"日志的日志"无限膨胀；代价是该前缀的查询/删除无审计留痕 | 与"审计不可抹"（#8）同源，见 04 |
| 登录失败不区分账号/密码错误业务码 | 统一 1002，配合 BCrypt dummy-hash，防邮箱枚举（计时侧信道已实测排除） | 登录失败限流仍待办（#18） |
| FORGOT_PASSWORD 对未注册邮箱静默跳过 | 防枚举、防垃圾邮件滥用 | 已实测响应一致 |
| 管理员建号与后台导入不走验证码 | 身份由 `user:create`/`user:import` 鉴权保障 | 导入的默认口令问题由 #4 收口 |

## 三、工程约束（非缺陷，但决定修复方式）

| 约束 | 影响 |
| :--- | :--- |
| 测试基座 `adminToken()` 走 service 直调 `assignRoles` 自绑 ADMIN | 修复 #1 时若加"授予 ADMIN 需超管身份"（闸 2）会破坏该链路 ⇒ 闸 2 排期后置，需同步迁移测试底座 |
| 业务异常统一 HTTP 200 + body 业务码 | 修复 #10 时**只对兜底 500** 加 `@ResponseStatus`，不能影响既有业务契约 |
| 权限缓存失效必须在改动关联表**之前**反查受影响用户 | 新增任何写权限/角色的逻辑都要遵守，否则缓存留脏至 TTL |
| `@Async` 不得自调用 | 新增异步逻辑（如审计限频 #9、投递重试 #15）需走外部 Bean 代理 |
