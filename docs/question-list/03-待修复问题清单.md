## 一、安全 / 校验

| # | 问题 | 严重度 | 修复方向 |
| --: | :--- | :--- | :--- |
| 18 | 登录无失败限制 + 可枚举邮箱 + BCrypt CPU 放大 | P1 | **本清单里最该做的一条**。失败计数 + 指数退避/锁定（Redis 原子脚本，与验证码解耦），**并加节流**——登录匿名且每次强制 BCrypt（实测 52ms/次），无节流即一个低成本的 CPU 打满入口。注意：计时侧信道**已实测排除**（见 [04](04-实测记录与核验方法.md) §三），别按侧信道修 |
| 25 | 权限缓存**回填覆盖竞态**（失效失败告警与坏值自愈已修） | P1 | 唯一「已识别但未闭合」的机制项。给缓存值加**版本号 + Lua 条件写入**：失效侧 INCR 版本，回填侧「版本未变才写」。注意旧值必然等于「更多权限」，竞态永远落在危险侧 |
| 12 | 认证硬依赖 Redis / 单节点 | P1 | **部署侧**：监控告警、Sentinel。**不轻易改脚本**——「补 hash tag 即可上集群」这个结论已补正为**不充分**（见 [02](02-主动放弃与搁置清单.md) §四.2） |
| 7 | CORS 通配（`*` + allowCredentials） | P2 | `SecurityConfig` 的 `allowedOriginPatterns("*")` 收敛为环境变量配置的允许源列表。当前不可直接利用（令牌走 `Authorization` 头、无 Cookie），是「前端一旦改用 Cookie 即升级」的潜伏面 |
| 13 | 令牌明文存储 Redis | P2 | 运维侧：AOF 权限、禁 `MONITOR`、slowlog 策略。改哈希存储需连三条 Lua + session 字段一起动，属大改 |

## 二、审计与可观测

| # | 问题 | 严重度 | 修复方向 |
| --: | :--- | :--- | :--- |
| 8 | 审计可一键抹除且不留痕（含**定向删除**更隐蔽） | P1 | 「清空 / 删除日志」动作强制入审（绕过切面直写）；评估物理删除 → 逻辑删除或保留期。与 #16 同源——若做加固，改为「只记删除动作、不记查询」 |
| 9 | 未认证请求无限写审计表 | P1 | 401 落库限频 / 降采样（异步线程池内过滤）+ 表的保留 / 归档策略（与 #32 的全表扫同源） |
| 10 | 真 500 以 HTTP 200 返回 | P1 | `handleException` 加 `@ResponseStatus(INTERNAL_SERVER_ERROR)`；**保持业务码 500 + 不泄露堆栈**，仅改 HTTP 状态。注意 401/403 的**双重表示**问题（URL 级 vs `@PreAuthorize` vs body 业务码） |
| 28 | MVC 层异常未被 handler 覆盖 ⇒ 500 + **不落审计** | P2 | 补 `BindException` / `MethodArgumentTypeMismatchException` / 405 / 413 等 handler，统一走 `recordAccessLog`。这几条当前既报成 5xx 又完全不落审计，形成「怎么打都不留痕」的探测面 |
| 30 | 数据层异常被归为「Redis 故障」 | P2 | `TokenAuthenticationFilter` 按异常类型分流（`DataAccessException` vs Redis 异常），分别给文案与「是否免审计」；否则 DB 抖动时全员 401 且审计零痕、日志还指向 Redis |

## 六、#4 的残留（已修项里唯一留尾的）

#4「默认凭据」的四条暴露面已全部收口（见 [01](01-问题清单.md)），但以下四点**有意留下**，
不要在文档里含糊带过：

1. **导入的初始口令仍是公开的**：`qsx123456` 在「导入 → 首次登录」窗口内有效，且整批共用同一个
   BCrypt hash。本轮只把它变成**临时**口令（首次登录即强制改密）；彻底方案是**逐行随机口令 +
   送达渠道**（邮件 / 导出回传），属产品决策。
2. **`admin123` 仍写在 `sql/init.sql` 与 README 里**：它现在是"首次登录用的临时口令"，
   但这一事实无法用代码消除——除非改成启动期引导设置口令，那会破坏开箱即用的本地流程。
3. **跑测试会把本地超管口令还原成 `admin123` + 标志 0**：测试底座的刻意自愈取舍，
   不复位会让 15 个测试类集体转红（见 [04](04-实测记录与核验方法.md) §六）。
4. **加列仍靠重跑 `init.sql`**（DROP 重建），无版本化迁移——即 #34；
   既有库升级需手工 `ALTER TABLE`（语句在 `sql/init.sql` 头部变更历史里）。
