## 二、未修复与残留项的明细

> 「本地可复现」的三种口径：✅ = 本机已实测复现；「本地可触发」= 本机操作即可复现但需刻意为之；
> 「仅并发/故障/部署形态」= 单人本地开发不会遇到。

### #7 CORS 通配（P2，读码）
`SecurityConfig` 的 `allowedOriginPatterns("*")` + `allowCredentials(true)`。**今天不可直接利用**：
令牌走 `Authorization` 头、无 Cookie、CSRF 关闭 ⇒ 恶意站点拿不到凭据。残余风险 = 任意网页可跨域
驱动匿名接口（含发信，见 #22）。它是「前端一旦改用 Cookie 即升级为 P1」的潜伏面。

### #8 审计可一键抹除（P1，读码）
`OperationLogServiceImpl.clear` 是全表 DELETE，`DELETE /api/logs/{id}` 是物理删除，且 `/api/logs`
前缀被切面整体排除（#16）⇒ **删除动作本身不留痕**。定向删除比一键清空更隐蔽。修法：「清空/删除日志」
动作强制入审（绕过切面直写）；评估物理删除 → 逻辑删除或保留期。

### #9 未认证请求无限写审计表（P1，读码）
`RestAuthenticationEntryPoint` 只对「Redis 基础设施异常」豁免落库；伪造 token 的 401 一律落库
（实测：匿名 30 次请求 = 30 行）。表只增不减。修法：401 落库限频/降采样 + 保留/归档策略（与 #32 同源）。

### #10 真 500 以 HTTP 200 返回（P1，读码）
`GlobalExceptionHandler.handleException` 无 `@ResponseStatus` ⇒ LB/监控看不到 5xx。
修法：**只对兜底 500** 加 `@ResponseStatus(INTERNAL_SERVER_ERROR)`，保持业务码 500 + 不泄露堆栈。
注意 401/403 的**双重表示**问题：URL 级未认证 = 真 401，`@PreAuthorize` = 真 403，
但 `CHANGE_PASSWORD` 场景未登录 = HTTP 200 + body 401。

### #12 认证硬依赖 Redis / 单节点（P1，部署侧）
Redis 故障 = 全员 401 且无法登录。修法在部署侧：监控告警、Sentinel。
**不要轻易改脚本**——`02 §四.2` 已补正：「上集群补 hash tag 即可」这个隐含结论**不充分**，
真要迁移需把键结构改成以 userId 为 hash tag 并改客户端契约。

### #13 令牌明文存储 Redis（P2，运维侧）
32 字节随机串不可枚举，但部署侧需收口 AOF 文件权限、禁 `MONITOR`、slowlog 策略。
改存 SHA-256 需同时改 `AuthRedisKeys` + 三条 Lua + session 字段，非单类可收敛。

### #15 邮件投递失败无重试/死信（P2）
投递失败只落 ERROR 日志。修法：队列 + 重试/死信告警（注意 `@Async` 不得自调用）；与 #22 同批。

### #17 / #24 导入解析异常与公式单元格（P2，实测）
- 公式**带**缓存值 → EasyExcel 抛 `NumberFormatException: Character a is neither a decimal digit…`
  → 经 `UserImportExportServiceImpl` 的 `catch (Exception)` 变成 **1017 + 英文原文回显**；
- 公式**不带**缓存值 → 该单元格**静默读成 `null`**。
修法同批：解析失败分支改固定文案（细节走服务端日志）；对 FORMULA 单元格给可读提示或显式拒绝。
（#17 是同一个 `e.getMessage()` 的另一条触发路径。）

### #18 登录无失败限制 + BCrypt CPU 放大（P1，**剩余安全项里最该做的**）
登录接口匿名、**零节流**、每次强制 BCrypt（**实测 52ms/次**）⇒ 撞库同时是一个低成本的 CPU
打满型 DoS。修法：失败计数 + 指数退避/锁定（Redis 原子脚本，与验证码解耦）+ 节流。
**注意**：计时侧信道**已实测排除**（存在/不存在邮箱各约 60ms，基线 2–3ms，Spring Security 的
`DaoAuthenticationProvider` 在 UsernameNotFound 分支跑了 dummy bcrypt）——别再把它当侧信道问题修。
「可枚举」只来自 `register`/发码的 1001。

### #25 残留：权限缓存**回填覆盖竞态**（P1，仅故障/并发形态）
`PermissionCacheServiceImpl.load` 是「未命中 → 查库 → `set` 回填」，**无版本号 / CAS**；
一旦与 AFTER_COMMIT 的删除交错，仍会把旧权限写回并续 30 分钟。因失效只在撤销时触发，
**旧值必然等于「更多权限」，竞态永远落在危险侧**；概率与**被影响用户的日常流量**成正比。
修法：给缓存值加版本号 + 用 Lua 做条件写入（失效侧 INCR 版本，回填侧「版本未变才写」）。

### #27 「查重 → 插入」TOCTOU（P2，仅并发形态）
`register`/`create`/`createMenu` 都是「先查重再插入」，未捕获 `DuplicateKeyException`
⇒ 并发/双击拿到 `body 500` 而非 1001/1010/1016。唯一索引已兜住一致性，缺的是业务码。

### #28 MVC 层异常未被 handler 覆盖（P2，本地可触发）
`GlobalExceptionHandler` 只覆盖 `BusinessException` / `MethodArgumentNotValidException` /
`HttpMessageNotReadableException` / `AccessDeniedException`，缺 `BindException`、
`MethodArgumentTypeMismatchException`、405、413 ⇒ 全部落到兜底 500，**且不像 400 分支那样补记审计**。
`GET /api/users/abc`、`PATCH /api/users/1` 即是——「怎么打都不留痕」的探测面。

### #30 数据层异常被归为「Redis 故障」（P2，仅故障形态）
`TokenAuthenticationFilter` 的 `catch (Exception)` 把查库异常也归到「Redis 不可达」并打上免审计标记
⇒ Redis 健康时只要 DB 变慢，全员 401、审计表零记录，ERROR 文案还把方向指向 Redis。
修法：按异常类型分流（`DataAccessException` vs Redis 异常）。

### #31 导入/导出上限在 OOM 之后才生效（P2）
导出是**先全表读进内存再判 50000 上限**；导入是**解析完整个 Excel 再判 1000 行**。
正确做法：导出改 `LIMIT n+1` 或先 `selectCount`；导入在 `ReadListener.invoke` 内计数即抛。

### #32 `pageNum` 无上限 + 全表扫（P2，本地可触发）
`pageSize` 有 `maxLimit=500`（已防护），`pageNum` 无 `@Min/@Max` ⇒ `?pageNum=100000000`
生成 `LIMIT 49999999500,500`；四个查询全用 `LIKE '%x%'`（前导通配符使 `uk_email` 完全用不上），
且 `%`/`_` 未转义（`?email=%` 可强制无条件全表扫）。

### #33 JSON 请求体无大小上限（P2，本地可触发）
只限制了 multipart（10MB）⇒ 匿名 `/auth/login`、`/auth/register` 可被巨大 body 打内存。

### #34 无版本化迁移（P2，工程规范）
仓库唯一 DDL 产物是 `sql/init.sql`，而它是 `DROP TABLE` + 重建、兼作种子数据 ⇒
schema 演进无路可走（此前每次加列都只能重跑整个脚本或手工 `ALTER`），误跑一次即全库清空。
也没有 profile 隔离（#5 的代码侧已另行落地）。修法：引入 Flyway，或至少把增量 DDL 独立成 `sql/migrations/`。

### #36 测试直连开发库且无守卫（P2，工程安全）
`BaseIntegrationTest` 直接跑在开发库上，清理范围含**清空 `sys_operation_log` 全表**。
修法：加「库名不含 test 就拒绝启动测试」的守卫（成本极低，防的是将来某次对着生产配置跑 `mvn test`）。

### #38 `sys_permission` 分页排序非全序（P2，本地可触发）
`PermissionServiceImpl.page` 只有 `orderByAsc(sort)`，缺 id tiebreaker（同类方法
`getUserMenuTree`/`selectAll` 都补了）⇒ `sort` 相同的行跨页顺序不稳定，翻页会重复/漏行。

### #39 菜单 `type`/`visible`/`sort` 无白名单（P2，本地可触发）
`MenuCreateRequest`/`MenuUpdateRequest` 的 `type` 是自由字符串，而代码按 `type == "MENU"` 判定
⇒ 写错一个字符，该菜单对所有用户的菜单树**静默消失**。`visible`/`sort` 同理无约束。

### #40 权限缓存无抖动、无单飞（P2，仅并发形态）
TTL 固定、写入时刻由各请求决定、未命中无单飞 ⇒ 一次角色/权限变更会把 N 个用户的键**同时**删除，
随后同一瞬间回填、同一时刻到期 ⇒「管理员改一次角色 = 半小时后一个 DB 尖峰」。
修法：TTL 加 ±10% 抖动 + 未命中回填加单飞。
