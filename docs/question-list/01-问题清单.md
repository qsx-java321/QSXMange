## 二、逐项明细（关键核实点）

### #1 自助提权（P0，当前修复）
- **位置**：`UserServiceImpl.assignRoles` / `UserImportExportServiceImpl.importUsers`（validateRow）
- **核实**：`assignRoles` 全方法仅校验"用户存在、角色存在"，无任何 ADMIN/超管检查；`import` 的 roleCodes 校验仅查编码存在。与 1020/1021/1025/1011/1026 的超管保护不对称。
- **三种危害**：① 低权限者给自己绑 ADMIN；② 任意操作者清空内置超管角色（架空超管，无恢复途径）；③ 导入 ADMIN 角色账号（口令公开、不强制改密）。

### #2 删除权限行（P0，当前修复）
- **位置**：`PermissionServiceImpl.delete`
- **核实**：只查"有子节点禁删"，对系统预置权限码无保护；删除会物理清 `sys_role_permission` 关联（连坐 ADMIN）；`uk_perm_code` 唯一索引含已删行 + `countByCodeIncludeDeleted` 判重 ⇒ 同 code 无法经接口重建。
- **危害**：误删一个权限码 → 对应接口全站 403 且 GUI 无法恢复。

### #3 Excel 公式注入（P0，当前修复）
- **位置**：`UserImportExportServiceImpl.exportUsers` / `UserExportRow`
- **核实**：导出原样写出 `nickname`（仅 `@Size(max=50)`，注册匿名）；EasyExcel 写入 `=` 开头字符串会被 POI 推断为公式。
- **危害**：管理员用 Excel 打开导出文件即触发公式执行（CWE-1236）。

### #4 默认凭据与明文（P0，后续修复）
- **位置**：`init.sql`（admin@qsx.com/admin123）、`application.yml`（`import.default-password=qsx123456` 且不强制首改、`StdOutImpl` SQL 明文、`com.qsx: debug`、MySQL root/123456、Redis 免密）
- **方案骨架**：见 04。
