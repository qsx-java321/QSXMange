# docs/test · 测试文档

> **本目录是 QSXManager 的测试文档中心**：测试报告、分域基线、复跑指引。
> 项目定位是本地开发 / 学习（不以真实投产为目标），测试采用**双轨制**：
> **Track A** 自动化集成测试（`mvn test`）+ **Track B** 真实 HTTP 测试（起 fat jar 逐接口调用）。

## 一、文档结构

```
docs/test/
├── README.md                  ← 本文件：唯一入口（文档地图 + 复跑指引）
├── 项目测试报告.md              ← 测试结果（Track A/B 汇总 + 正向/反向/边界明细）
└── 分域基线/                   ← 自动化用例的分域索引（长期有效）
    ├── 01-认证与会话.md
    ├── 02-邮箱验证码.md
    ├── 03-用户与保护矩阵.md
    ├── 04-角色权限RBAC.md
    ├── 05-菜单与操作日志.md
    ├── 06-Excel导入导出.md
    └── 07-邮件投递与DEBUG验证码通道.md
```

**两层职责**：

| 层 | 文件 | 回答什么问题 |
| :--- | :--- | :--- |
| 结果层 | [项目测试报告.md](项目测试报告.md) | 测了什么？结果如何？哪些接口正/反/边界都覆盖了？**例数**是多少？ |
| 索引层 | [分域基线/](分域基线/) | 某个接口对应哪个测试类？该域有哪些断言点与业务码落点？ |

> **分工原则**：分域基线只记**稳定的**「接口 ↔ 测试类 ↔ 断言点 ↔ 业务码落点」；
> **例数**（会随每次改动变化）只在报告 §四.1 记一份，避免两处对不上。
> 各分域内的「⏳ 历史快照 · Track B」小节是**当轮真实 HTTP 记录**，不代表当前，
> 当前的正向 / 反向 / 边界结果以报告 §六~§八 为准。

## 四、如何复跑

### 4.1 前置条件

- JDK 21、Maven 3.9+；
- Docker 起 **MySQL 8.4**（`3306`，root/123456）与 **Redis 7.4**（`6379`）——两者**都必须可用**，Redis 是认证链路硬依赖；
- **Mailpit**（SMTP `1025` / Web UI `8025`）：跑全量时保持运行，否则 `CaptchaMailSmokeTest` 会 `assumeTrue` 跳过。

### 4.2 Track A · 自动化

```bash
mvn -o clean test                     # 全量 257 例（改动跨模块签名后务必先 clean）
mvn test -Dtest=SessionLuaTest -Dsurefire.failIfNoSpecifiedTests=false   # 单类（该参数必带）
```

> ⚠️ 测试**复用本地开发库与开发 Redis**：不要在应用正服务会话时跑，会清掉在线会话的键。
> 跑一次会把**预置超管复位**为 `admin123` + `must_change_password=0`。

### 4.3 Track B · 真实 HTTP

```bash
# 1. 重建库（会清空既有数据）
docker cp sql/init.sql mysql:/tmp/init.sql
docker exec mysql sh -c "mysql --default-character-set=utf8mb4 -uroot -p123456 < /tmp/init.sql"

# 2. 打包并启动（只有 qsx-admin 可执行）
mvn -o -DskipTests package
java -jar qsx-admin/target/qsx-admin-1.0.0.jar      # http://localhost:8080
```

全新库的超管带 `must_change_password=1`：**先走一次首次改密**（`admin123` → 新口令），
否则除 `/auth/**` 外的接口一律返回业务码 **1037**。

### 4.4 清理红线

- 造数一律 `*@test.com`（用户）与 `test-` 前缀（角色/菜单）；**禁止全表删除**（会删掉预置超管）。
- 清理要点与工具坑（`curl.exe`、`Invoke-WebRequest` 不发 JSON CT、Hibernate `@Email` 本地部分 ≤64 等）见
  [项目测试报告.md 附录 A](项目测试报告.md#附录-a--测试执行要点复用时注意)。

## 五、维护约定

1. **一轮测试 = 更新 `项目测试报告.md`**，不新增报告文件。
2. **实施类计划文档在功能交付后归档删除**（内容并入本目录报告与 `docs/session-notes/`，历史见 git 记录）——
   本目录当前**不保留计划文档**。
3. **接口行为的权威依据是 [`docs/design/`](../design/) 与当前源码**；本目录是测试视角。
   分域基线已于 2026-10-01 对齐至 `b5c922b`（补齐 1033~1037 保护闸、验证码第五键 `ipdaily`、
   以及若干缺陷修复批次）；**若此后代码再变更，仍以设计文档与源码为准**。
4. 分域基线**不记例数**（唯一数据源是报告 §四.1）；新增接口须同步补测试
   （鉴权正反向、业务码矩阵、边界、机制层断言），并更新报告的覆盖矩阵。
