## 五、基础设施、审计与回归验证

- **统一返回 / 错误码**：业务异常体系（1001~1032 分段）与「HTTP 200 + body 业务码」契约，经 `BusinessFlowTest` 与各域边界用例验证。
- **异常处理**：参数校验 400、`HttpMessageNotReadable`→400、`AccessDenied`→403、兜底 500（`GlobalExceptionHandler`）。
- **审计链路**：`OperationLogAspect` 异步落库；401 由 `RestAuthenticationEntryPoint` 补记；Redis 故障期 401 跳过落库（防写风暴）。`LogTest` 校验落库行为。
- **机制层**：会话三键/TTL、权限缓存键失效、验证码四键生命周期均由直查 Redis/SQL 断言（详见各分域报告 §机制层）。
- **回归兜底**：`RefactorRegressionTest` 6 + `BusinessFlowTest` 3 全绿，确认多模块拆分与改密/验证码重构未引入静默失效。

## 六、已知缺口（沿用，非本轮发现，来源：设计 `05-业务功能与保护矩阵.md` §7）

| # | 缺口 | 影响 |
| --: | :--- | :--- |
| 1 | 删除权限行无保护 | 误删权限码行 → 对应接口全站 403 且无法经接口重建 |
| 2 | 审计可一键抹除且不留痕 | `log:delete` 可整体清空审计 |
| 3 | 未认证请求可无限写审计表 | 伪造 token 的 401 一律落库，表持续膨胀 |
| 4 | 两条自助提权路径无护栏 | `assignRoles` 可绑 ADMIN；`user:import` 可导入 ADMIN 账号且不强制改密 |
| 5 | Excel 导出公式注入 | 昵称 `=...` 开头触发（本轮已测 Excel，未做攻击构造，仍留待办） |
| 6 | 默认凭据 / CORS 通配 / 异常对 HTTP 层隐藏 / 登录无失败限制 / 删除用户残留关联行 | 见设计 05 §7 |
