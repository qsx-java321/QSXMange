**鉴权三态分工**（各轮共同验证的核心契约）：

| 状态 | 触发 | HTTP | body code |
| :--- | :--- | :--- | :--- |
| 未登录 / 令牌已吊销 / 账号被禁用 | 无令牌、伪造令牌、登出·踢人·禁用·删除·改密后、`status != 0` | **401** | 401 |

| 账号仍用初始口令 | `must_change_password=1` 且 URI 不以 `/auth/` 开头 | **200** | **1037** |

优先级固定为 **认证(401) → 准入闸(1037) → 授权(403)**。

## 五、基础设施、审计与回归验证

- **统一返回 / 错误码**：业务异常体系（1001~1037）与「HTTP 200 + body 业务码」契约，经 `BusinessFlowTest` 与各域边界用例验证。
- **异常处理**：参数校验 400、`HttpMessageNotReadable`→400、`AccessDenied`→403、兜底 500（`GlobalExceptionHandler`）；不支持的 Content-Type、路径变量类型不匹配等 MVC 层异常不经该处理器，由容器直接返回 500（见 §七 7.3）。
- **审计链路**：`OperationLogAspect` 异步落库；401 由 `RestAuthenticationEntryPoint` 补记；403 由切面/`RestAccessDeniedHandler` 补记；400 由异常处理器补记；**1037 由 `TokenAuthenticationFilter` 补记**（各轮均已实测）。Redis 故障期 401 跳过落库（防写风暴）。
- **机制层**：会话三键/TTL、权限缓存键失效、验证码键生命周期均由直查 Redis/SQL 断言（见 §九）。
- **回归兜底**：`RefactorRegressionTest` 6 + `BusinessFlowTest` 3 全绿，确认多模块拆分与改密/验证码重构未引入静默失效。

## 七、真实 HTTP · 第二轮：反向（拒绝路径）

> 范围：拒绝路径。**约 169 项全部通过**。身份矩阵：`T_admin`（超管）· `T_noperm`（零权限）· `T_limited`（仅 `user:page`）· `T_op`（非超管的特权操作者）· `T_pending`（待首次改密）。

### 7.1 认证与会话（401 / 1019 / 1027~1032 / 1037）

| 类别 | 实测 |
| :--- | :--- |
| **401 令牌形态** | 无令牌 · 伪造令牌 · 缺 `Bearer ` 前缀 · 空令牌 · 受保护接口无令牌 → 均 **HTTP 401 + code 401** |
| **401 即时吊销** | 登出 / 改密 / 被踢 / 被禁用 / 被删除 / 单端覆盖后，旧 AT → **401**（机制层见 §九） |
| **登录拒绝** | 密码错 → **1002**；邮箱不存在 → **1002**（同码防枚举）；已禁用 → **1003** |
| **刷新令牌** | 空串 → **400**（`@NotBlank` 先于服务层）；格式错 / 已轮换 / 已登出 / 已禁用 → 均 **1019** |
| **注册唯一性** | 已注册邮箱注册 → **1001**；发 REGISTER 码给已注册邮箱 → **1001** |
| **验证码发送** | 同 `{scene}:{email}` 60s 内二次发送 → **1027** |
| **验证码校验** | 填错 → **1028**；**第 5 次错 → 1029**（作废）；作废后用原正码 → **1028**（码已删） |
| **改密通道** | 两通道都不传 / 都传 → **1031**；原密码错 → **1006**；他人邮箱发码 → **1032** |
| **忘记密码** | 两次密码不一致 → **1030**；未注册邮箱 → **1028**（防枚举） |
| **准入闸 1037** | 待改密账号访问 `/api/users` → **HTTP 200 + 1037**（**证明 1037 先于 403**）；访问 `/auth/**`（me/refresh/captcha/logout）全部豁免；被拦时审计补记 `success=0` |
| **不对称性** | 待改密账号**被禁用**后 → **401 而非 1037**（1037 判定位在 `isEnabled()` 分支内） |
| **双层码特例** | `/auth/captcha`(CHANGE_PASSWORD) 未登录 → **HTTP 200 + body 401**（URL 层 permitAll、业务层判未登录） |

### 7.2 授权 403

`T_noperm`（零权限）遍历**全部 29 个受 `@PreAuthorize` 保护的端点** → 一律 **HTTP 403 + code 403**。
反向确认：`GET /api/menus/current` 是「登录即可」→ **200 + code 200**（零权限返回空树）；`T_limited` 有权限的接口 **200**、无权限的仍 **403**。

### 7.3 参数校验 400

24 类字段校验用例全部 **HTTP 200 + code 400** 且消息精确：邮箱格式/长度、密码长度与强度、状态取值、角色码与名称长度、菜单 `type` 白名单、`visible`/`sort` 范围、`scene` 枚举、必填缺失、非法 JSON、空 body。

| 触发 | HTTP | code | 归因 |
| :--- | :--- | :--- | :--- |
| 字段校验失败 / 非法 JSON / 枚举非法 / **空 body** | 200 | 400 | 已被 `GlobalExceptionHandler` 覆盖 |
| **Content-Type 不受支持**（`text/plain`） | 200 | **500** | 抛 `HttpMediaTypeNotSupportedException`，未被全局异常处理器覆盖 |
| **路径变量类型不匹配**（`/api/users/abc`） | 200 | **500** | 未进入全局异常处理器，由容器返回 |
| 查询参数格式非法（`beginTime=2026-13-99`） | 200 | **400** | 已被全局异常处理器覆盖 |

### 7.4 用户 / 角色 / 菜单权限业务码

| 域 | 用例 | 实测 |

## 附录 A · 测试执行要点（复用时注意）

### A.1 会话与令牌

1. **单端登录**：同账号重新登录会使旧 AT/RT **立即失效**——构造「令牌立即失效」类用例必须「先登录留存令牌 → 再触发失效 → 再请求」。
2. **刷新即吊销旧 AT**：`POST /auth/refresh` 成功后旧 AT 立刻 401，后续步骤必须改用新 token。
3. **五类操作后令牌立即失效**：登出 / 踢下线 / 禁用 / 删除 / 改密；改密后旧 RT 也会变成 1019。
4. **1037 闸**只放行 `/auth/` 前缀；需要全权令牌的用例必须先完成超管首次强制改密。

### A.2 验证码额度（易踩）

- 发送间隔 **60 秒**（`{scene}:{email}` 维度）；每邮箱每日 **10 次**；每 **IP 每日 30 次**（跨场景跨邮箱累计）。
- 校验错 **5 次**即作废（第 5 次返回 1029），作废后原正确码也返回 1028。
- 排期建议：把「错次上限」用例排在同类之前，集中复用同一枚码，并留意 IP 日限。

### A.3 保护码用例的正确姿势

- **只做拒绝断言**：内置资产（ADMIN 角色、预置菜单/权限码、超管账号）**绝不能真的删除或停用**。
- **拒绝后必须回查**目标状态未变（`status` / 角色绑定 / `permissionIds`）——验证「拒绝即终态」。
- **注意优先级**：测 `1033` 时操作者不能是目标本身（否则 `1022` 先命中）；`DELETE /api/menus/{id}` 的 `1035` 先于 `1014`。

### A.4 工具与构造

- Windows PowerShell 下 `curl` 是 `Invoke-WebRequest` 别名，用 **`curl.exe`**；JSON 复杂体建议写临时文件用 `--data @file`。
- `Invoke-WebRequest` 在**无 body 时不会发送** `Content-Type: application/json`（默认成 form）——需要「空 body + JSON CT」时必须用 `curl.exe --data-binary ''`。
- PowerShell 中 **`$pid` 等为只读自动变量**，造数脚本勿用作变量名。
- 校验邮箱长度边界时，**本地部分需 ≤ 64 字符**（Hibernate `@Email` 限制）；测 101 字符可用 `local(64) + '@' + domain(36)`。
- Excel 反向用例可用 Python 标准库 `zipfile` + `inlineStr` 生成最小 xlsx，无需引入依赖。

### A.5 环境与清理

- 测试复用**本地开发库与开发 Redis**：**不要在应用正服务会话时跑 `mvn test`**（会清 Redis 会话键）。
- 造数一律 `*@test.com`（用户）与 `test-` 前缀（角色/菜单），结束后按此清理；**禁用全表删除**（会删掉预置超管）。
- 跑一次 `mvn test` 会把**预置超管复位**为 `admin123` + `must_change_password=0`。
