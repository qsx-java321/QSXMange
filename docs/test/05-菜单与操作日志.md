## 机制层断言

- 菜单删除前先清角色-权限关联再逻辑删除（Track A `MenuTest`），改菜单后相关联用户权限缓存失效（Redis 直查）。
- 审计写入由 `OperationLogAspect` 异步落库（Track A `LogTest` 校验 operation_log 行数与 success 语义）。

## 发现的问题 / 观察项

- `GET /api/menus/current` 的 200 happy path 由 Track A `MenuTest` 覆盖；Track B 仅验证「已登出 token → 401」的边界，属编排取用已登出 token，非缺陷。
- 已知缺口（设计 05 §7）：`/api/logs` 前缀被切面整体排除（其查询/删除不进审计表）、
  持 `log:delete` 可一键抹除审计且不留痕——#8 已随尺度回调**撤销**（单人项目无追责/合规
  威胁模型）、#16 保持**主动搁置**（防「日志的日志」膨胀的取舍），见 `docs/question-list/`。
