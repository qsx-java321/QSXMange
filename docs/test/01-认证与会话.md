## 机制层断言（Redis 直查）

- 登录/刷新后 `qsx:auth:at:{at}`、`qsx:auth:rt:{rt}` 均存在且 TTL 合法（由 SessionLuaTest 在 Track A 逐键断言）。
- 登出后三键（at/rt/session）随之删除 → 认证即 401，证明确为「删键即吊销」而非每请求查库兜底。

## 发现的问题 / 观察项

- 无新增产品缺陷。本域抛出的 `1020/1021/1022/1025`、`1001/1002/1004/1019` 均与保护与业务码设计一致。
- Track B 曾在编排中将「刚被登出的 token」用于查询，返回 401——属测试数据误用，非缺陷（Login 后重拿 token 即恢复正常）。

## 结论

认证与会话链路（登录/刷新/登出/me/改密/忘记密码 + 三键吊销 + 单端覆盖 + 严格轮换）在 Track A（50 例）与真实 HTTP 双轨下全部符合预期，无回归。
