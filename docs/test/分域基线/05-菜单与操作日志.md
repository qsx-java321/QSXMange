## 保护码落点（本域）

| 码 | 触发 |
| :--- | :--- |
| 1013 | 菜单不存在（`PUT` / `DELETE /api/menus/{id}`） |
| 1014 | `DELETE /api/menus/{id}` 存在子节点 |
| 1015 | `POST /api/menus` 父节点不存在或非 `MENU` 行；`PUT /api/menus/{id}` 父指自身或其子孙（**防环**） |
| 1016 | `POST /api/menus` 标识重复（`countByCodeIncludeDeleted`，**含逻辑删除行**） |
| 1023 | `PUT /api/menus/{id}` **改 code**（标识创建后不可修改） |
| **1035** | `DELETE /api/menus/{id}` 目标 code ∈ `BUILT_IN_CODES`（**29 个预置码**：23 个按钮权限码 + 6 个菜单入口码） |

> **`DELETE /api/menus/{id}` 优先级**：`1013（不存在）→ 1035（内置）→ 1014（有子节点）`。
> 1035 刻意排在 1014 之前：一个「既有子节点又是内置」的节点（如 `system`），
> 先报「内置不可删」比先报「有子菜单」更接近操作者真正需要知道的原因。
>
> 1035 的意义：删掉内置权限码行 → 对应接口对**所有人永久 403**（连坐清掉 ADMIN 关联），
> 而 `uk_perm_code` 是物理唯一索引 + 判重含已删行 ⇒ 同 code 无法经接口重建，只能改库。

## 参数白名单

菜单的 `type` / `visible` / `sort` 三个取值歧义字段**都有白名单与范围校验**，缺失会导致静默失配：

| 字段 | 约束 | 缺失后果 |
| :--- | :--- | :--- |
| `type` | `MENU` \| `PERMISSION`（创建时可留空，默认 `MENU`；修改时必填） | 写错一个字符（如 `menu`）→ 该菜单对所有人的菜单树**静默消失**（树按 `type == "MENU"` 过滤） |
| `visible` | `0` \| `1` | 语义歧义 |
| `sort` | `0 ~ 9999` | 语义歧义 |

## 机制层断言

- 菜单删除：**先清角色-权限关联再逻辑删除**；`update` / `delete` 均在**改动前**反查持有者并失效其权限缓存。
- 审计写入由 `OperationLogAspect` 对 `com.qsx.web.controller` 包级扫描、以 `Result.code == 200` 判成功、
  经 `AccessLogRecorder` 端口**异步**落库（`@Async` 靠 Spring 代理，**不得自调用**）。
- `/api/logs` 前缀被切面整体排除 → 日志的查询与删除都不进审计表（设计取舍）。
- `POST /api/menus` 在 INSERT 处捕获 `DuplicateKeyException` 映射回 **1016**。
