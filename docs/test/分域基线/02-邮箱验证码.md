## 五键模型（当前实现）

| Key | 含义 | TTL |
| :--- | :--- | :--- |
| `qsx:auth:cap:{scene}:{email}` | 6 位验证码（明文） | 5m |
| `qsx:auth:cap:attempt:{scene}:{email}` | 错误计数，达 `max-attempts` 即作废 | 与码同生共死 |
| `qsx:auth:cap:limit:{scene}:{email}` | 发送间隔标记（`SET NX`） | 60s |
| `qsx:auth:cap:daily:{yyyyMMdd}:{scene}:{email}` | 当日发送计数（每邮箱每日 10） | 24h（日期串键） |
| `qsx:auth:cap:ipdaily:{yyyyMMdd}:{ip}` | **同 IP 当日发送计数**（跨场景 / 跨邮箱，默认 30） | 24h（日期串键） |

> ⚠️ **第五键 `ipdaily` 于 2026-09-29 新增**：只按邮箱限流时「换个邮箱就有新额度」，
> 等于给了一个向任意地址群发的公开接口。
> 发送与校验两条 Lua（`captcha_send.lua` / `captcha_verify.lua`）必须与使用方同模块。

## 机制层断言（Redis 直查）

- 发送后码键**存在**；注册 / 改密 / 重置使用后**被删除**（用后即焚，由 Lua 原子保证，防并发双花）。
- 未注册邮箱走 FORGOT_PASSWORD：码键**不存在**——「响应与成功一致 + 未落码」构成双重防枚举。
- 发送侧「限流标记 + 当日计数 + 落码 + 清零错次」写在**同一条 Lua** 内：
  拆成 Java 侧 `INCR` + `EXPIRE` 会留下无 TTL 的键（永久锁死）或让日限退化成滑动窗口。
- `limit` / `attempt` 键分属不同维度，TTL 语义由 Track A 断言。

## 业务码落点（本域）

| 码 | 触发 |
| :--- | :--- |
| 1027 | 发送过于频繁（间隔 / 邮箱日限 / **IP 日限**共用同一码与文案） |
| 1028 | 验证码无效（**不存在 = 已过期 = 填错，同码同文案**） |
| 1029 | 错误次数超限（达到 `max-attempts` 即作废；**第 5 次错返回此码，之后原正确码也失效**） |
| 1030 | 忘记密码两次输入不一致（**先于**验证码校验） |
| 1031 | 改密两通道都不传 / 都传 |
| 1032 | CHANGE_PASSWORD 场景发码给非本人邮箱 |

> **校验顺序统一为「前置条件 → 验证码」**（注册是「唯一性 → 验证码」）：校验成功即用后即焚，
> 先校验会把用户手里那张有效的码烧掉。
