## 机制层断言

- 删除用户 → email 改写为 `#deleted_<时间戳>` + 逻辑删除（Track A `UserEdgeTest` 断言），唯一索引随之释放、同邮箱可重注册。
- 禁用/踢人/删除 → 会话三键清空、旧 AT 立即 401（Track A `UserKickTest` / `AuthSessionTest` 直查 Redis 断言）。

## 发现的问题 / 观察项

- Track B 的 `kick`/`delete` 因测试编排给目标用户授了 ADMIN 角色而在 1021/1025 处被拦（保护正确触发），普通用户的正常踢人/删除「200」happy path 由 Track A `UserKickTest`/`UserEdgeTest` 覆盖。
- 已知缺口（设计 05 §7）：删除用户残留 `sys_user_role` 孤儿行（主动搁置）。

## 结论

用户 CRUD、分页、整表替换角色、以及 1020/1021/1022/1025 + 403 保护矩阵在双轨下全部符合预期；保护判定采用「非本人 + 内置超管」组合语义，无绕过。
