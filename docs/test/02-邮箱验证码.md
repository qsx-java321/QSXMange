**机制层断言（直读 Redis）**

- 发送后码键【存在】；注册/改密/重置使用后【被删除（用后即焚）】。
- 未注册邮箱 forgot → 码键【不存在】——「响应与成功一致 + 未落码」，双重防枚举成立。
- 发送间隔与错次计数键分属 `limit` / `attempt`，由 Track A 断言 TTL 与「同生共死」语义。

## 发现的问题 / 观察项

- 未订阅真实投递（`SmtpEmailService` → Mailpit），本轮不验证邮件最终送达——属计划内排除，非缺陷。接入真实 SMTP 后建议补一条端到端冒烟。
- `DEBUG`（`qsx.captcha.debug=true` 直返码）未在本轮覆盖，设计上仅限本地联调。

## 结论

验证码「发送限流 → 落码 → 用后即焚 / 错次作废 / 防枚举」四大能力在双轨下均符合预期，Redis 四键生命周期正确。
